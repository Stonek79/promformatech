# ПромФормаТех

Сайт-витрина: Next.js 16, React 19, Payload 3, SQLite. Русская админка, черновики и предпросмотр, медиатека с фоновой обработкой. Docker и отдельный сервер базы больше не нужны.

## Разработка

Node.js 22.23.5, pnpm 10.12.4, FFmpeg/FFprobe в PATH.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

Сайт `http://localhost:3000`, админка `/admin`. Команда `pnpm dev` создаёт отсутствующий `.env` и каталог базы, применяет миграции SQLite, добавляет начальные материалы в новую базу и запускает Next.js и обработчик фото и видео. На новой локальной базе создайте владельца при первом входе. `Ctrl+C` останавливает оба процесса.

Если старая локальная база ещё не переведена на локали, команда один раз сохраняет копию в каталоге `before-localization.*` рядом с базой и выводит её путь. Если схема уже соответствует миграциям, достаточно обновить журнал.

При переходе со старой версии укажите `DATABASE_URL=file:./private/database/site.sqlite` в существующем `.env`. Относительный путь считается от каталога `app`. Для уже созданной пустой базы начальные материалы можно добавить командой `pnpm seed`. Не запускайте dev и production на одном файле базы.

## Проверка перед коммитом

После установки зависимостей подключите хук один раз из корня репозитория.

```bash
git config --local core.hooksPath .githooks
```

При коммите Biome проверяет только подготовленные версии изменённых файлов в `app` с учётом настроек `app/biome.json`. При ошибке исправьте файл, снова выполните `git add` и повторите коммит.

Тесты запускайте локально из `app` перед отправкой изменений. Для обычной правки начните с `pnpm check` и запустите браузерные сценарии затронутого раздела, например `pnpm test:e2e product-layout.spec.ts`. Для полного прогона используйте `pnpm test:e2e` без имени файла; если Chromium ещё не установлен, сначала выполните `pnpm exec playwright install --only-shell chromium`. Изменения в базе и обработке медиа проверяйте командами ниже, а серверные скрипты — через `python3 -B -m unittest discover -s ../deploy/tests -v`.

## Команды

| Команда                 | Назначение                                                     |
| ----------------------- | -------------------------------------------------------------- |
| `pnpm check`            | Biome, лимит 300 строк, типы, CSS, быстрые unit-проверки       |
| `pnpm test:e2e <файлы>` | Chromium и отдельная SQLite, без рабочего контента             |
| `pnpm test:integration` | Пустая SQLite, миграции, версии и восстановление медиа         |
| `pnpm test:media`       | Sharp/FFmpeg                                                   |
| `pnpm build`            | Production standalone без рабочей базы и секретов              |
| `pnpm release:build`    | Сборка плюс production-зависимости и CLI для текущей платформы |
| `pnpm release:verify`   | Проверка готового релиза вне исходного проекта                 |
| `pnpm db:migrate`       | Проверенные миграции; web/worker перед этим остановлены        |
| `pnpm cms:create-owner` | Первый владелец через OWNER_EMAIL/OWNER_PASSWORD               |

Для VPS берите артефакт Linux x64 из GitHub Actions, не локальный macOS build. На сервере запускаются `node server.js` и `node ops/worker.mjs once` под systemd; установка npm-пакетов там не требуется.

Контент, аккаунты и версии живут в SQLite; медиа — в MEDIA_ROOT, секреты — в `.env`. GitHub хранит код, но не эти данные. Нужны согласованные внешние копии и проверка восстановления.

Публичной формы, архива заявок и политики обработки данных нет. SMTP оставлена только как необязательная доставка восстановления паролей. Настройки сайта публикуются через черновик; служебный раздел владельца показывает состояние подключений.
