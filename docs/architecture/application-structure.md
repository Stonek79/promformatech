# Структура приложения

Приложение находится в `app`. Граница текущей реализации — локально проверяемые
админка и публичный сайт из согласованного плана. Переключение действующего
домена, покупка сервисов и публикация в production отдельно не разрешены.

| Каталог внутри `app/src` | Ответственность |
|---|---|
| `app/(site)` | Публичные маршруты и композиция страниц |
| `app/(payload)` | Маршруты Payload, предпросмотра, заявок и защищённой выдачи медиа |
| `cms` | Схемы коллекций и globals, права, hooks, задачи очереди, дополнения админки |
| `features/content` | Чтение опубликованных материалов и разрешённых черновиков, отображение блоков |
| `features/media` | Неизменяемые исходники, подготовка производных, выдача файлов и HTTP Range |
| `features/leads` | Валидация обращений, ограничение частоты, сохранение и уведомления |
| `components/ui` | Общие небольшие элементы интерфейса и доступное поведение |
| `components/site` | Шапка, подвал и композиции сайта |
| `design-system` | Источник токенов и генерируемые CSS-переменные/media-условия |
| `config` | Доменные константы: маршруты, роли, состояния, лимиты и политика медиа |
| `payload-types` | Генерируемые типы по сущностям и регистрация типов Payload; максимум 300 строк в модуле |
| `lib` | Небольшие функции без привязки к экрану: ссылки и адреса страниц |

Маршруты остаются тонкими: HTTP-проверки и вызов функционального модуля.
Бизнес-текст хранится в CMS, стартовое наполнение — в отдельном seed.
Серверные модули не импортируются клиентскими компонентами. В клиент передаются
только данные, нужные конкретному элементу; состояние форм и диалогов локальное.

Обработка тяжёлых медиа выполняется задачами PostgreSQL/Payload, а не HTTP-запросом
публикации. Производные финализируются атомарно до изменения состояния на «Готово».
Сырой каталог загрузок не публикуется. Оригиналы доступны только сотрудникам;
анонимные посетители получают готовые файлы, связанные с опубликованным контентом.

Проверки: Biome, TypeScript, Stylelint и проверка дизайн-токенов; Vitest для
чистых правил и Playwright для сценариев менеджера и адаптивности. Тестовые
браузеры, сервер и media worker запускаются последовательно для ограничения
расхода памяти. Разработка и сборка используют штатный Turbopack из Next.js.
Пользовательские медиа читаются из runtime-тома и не трассируются как файлы сборки.

Опубликованные чтения используют отдельный кэш `features/content/cache.ts`;
авторизованный preview обходит его. Cache Components/PPR отключены из-за
воспроизведённой несовместимости pinned Payload/Next/Webpack при выходе из preview.
Фактические проверки и границы поставки: [состояние реализации](../implementation-status.md).

Типы схем Payload проходят штатный генератор и AST-преобразование: `any`
заменяется на `unknown`, сущности разделяются на модули, а имена коллекций
в `Config` связываются с константами. Публичный импорт `@/payload-types`
сохраняется. Промежуточный монолит удаляется автоматически.
