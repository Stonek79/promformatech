# Тексты интерфейса и будущие переводы

Исходный язык — русский. Публичный интерфейс доступен на русском, английском
и немецком. Язык задаёт URL. Русские адреса без префикса,
английские начинаются с `/en`, немецкие — с `/de` (`lang="de"`).

## Реализовано

- `app/src/i18n/config.ts`: поддерживаемые языки, язык по умолчанию,
  безопасная проверка внешнего значения языка.
- `app/src/i18n/locales/`: именованные группы текстов. `Messages` описывает
  структуру словаря; каждый следующий язык должен удовлетворять тому же типу.
- `getMessages(locale)`: выбор словаря для серверного кода.
- `MessagesProvider` / `useMessages`: выбор языка клиентских элементов без
  хардкода текста в JSX. Собственные компоненты админки получают язык от
  штатного TranslationProvider Payload через `AdminMessagesProvider`.
- Названия строк массивов CMS преобразуются в штатные локализованные labels
  Payload. Ключи данных, API и коллекций остаются техническими идентификаторами.

В словарь переведены настройки отображения, состояния загрузки, диалог,
шапка/подвал, подписи медиа, панель preview, запасные подписи формы и сообщения
валидации, восемь групп действий добавления строк CMS. В русском интерфейсе
настройки Payload имеют приоритет над запасными подписями. В английском и
немецком интерфейсах системные подписи берутся из словаря. Меню и тексты
подвала редактируются в Payload по языкам.

Тексты остальных ранее созданных схем CMS, справочника, отдельных страниц
и служебных экранов ещё предстоит постепенно перенести в словари. Они остаются
русскими. Демонстрационные данные UI kit и тестовые материалы не являются
словарём переводов продукта.

## Правила для нового кода

1. Добавить смысловой ключ в нужную группу словаря, затем использовать его
   в компоненте. Не создавать константы с тем же текстом в каждом файле.
2. Не склеивать переводимые предложения из независимых фрагментов. Для имени
   компании или медиа использовать функцию сообщения с типизированным параметром.
3. Публичный текст, который должен менять менеджер, хранить в CMS. Словарь
   предназначен для интерфейса и безопасных запасных значений.
4. Не переводить slugs коллекций, имена полей и значения состояний.
5. Новые словари проверять через `satisfies Messages`; большие группы разбивать
   по смыслу, соблюдая лимит файлов проекта.

## Что потребуется для перевода наполнения

В Payload локализованы названия и адреса офисов, должности, подписи пунктов
меню и ссылок в подвале, заголовок подвала, часы работы и копирайт. Карта,
телефон, почта, URL и порядок пунктов общие для трёх языков. Подвал использует
карточку с флажком «Использовать адрес и карту в подвале».

Пустое поле подставляется из русского поля той же записи. Для строк массива
совпадение определяется по ID, а HTML получает язык фактического текста.
Так же локализованы название и заголовок страницы, тексты и подписи в блоках,
заголовок и описание для поисковиков. Для пустого поля используется русский
текст, включая пустые документы редактора Lexical. Адрес, структура блоков,
ссылки и вложения общие. Для продукции, услуг и проектов локализованы также
описания и подписи в галереях, для продукции — характеристики, для проектов —
тексты задачи, решения и результата. Поиск использует текущий и русский языки
для названий и коротких описаний карточек.

Черновик страницы, карточки или настроек открывается на выбранном языке. Публикация
записи общая для всех языков. Миграция локализации переносит русский текст
страниц, карточек и их версий, включая сохранённые черновики и содержимое блоков.

Сейчас на `/en` и `/de` действует `noindex`, sitemap содержит русские
страницы. Индексация переведённых страниц и отдельный выпуск переводов
потребуют собственных правил публикации.
Язык интерфейса админки и язык редактируемого материала выбираются независимо.

Наличие словарей само по себе не делает содержимое сайта многоязычным.
