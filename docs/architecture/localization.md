# Тексты интерфейса и будущие переводы

Исходный язык — русский. Сейчас включён только `ru`; переключатель языка
не показывается. Новые зависимости для этого не добавлены.

## Реализовано

- `app/src/i18n/config.ts`: поддерживаемые языки, язык по умолчанию,
  безопасная проверка внешнего значения языка.
- `app/src/i18n/locales/ru.ts`: именованные группы текстов. `Messages` описывает
  структуру словаря; каждый следующий язык должен удовлетворять тому же типу.
- `getMessages(locale)`: выбор словаря для серверного кода.
- `MessagesProvider` / `useMessages`: выбор языка клиентских элементов без
  хардкода текста в JSX. Собственные компоненты админки получают язык от
  штатного TranslationProvider Payload через `AdminMessagesProvider`.
- Названия строк массивов CMS преобразуются в штатные локализованные labels
  Payload. Ключи данных, API и коллекций остаются техническими идентификаторами.

В словарь переведены настройки отображения, состояния загрузки, диалог,
шапка/подвал, подписи медиа, панель preview, запасные подписи формы и сообщения
валидации, восемь групп действий добавления строк CMS. Отображаемые данные
Payload имеют приоритет над запасными подписями словаря.

Тексты остальных ранее созданных схем CMS, справочника, отдельных страниц
и служебных экранов ещё предстоит постепенно перенести в словари. Они остаются
русскими. Демонстрационные данные UI kit и тестовые материалы не являются
словарём переводов продукта.

## Правила для нового кода

1. Добавить смысловой ключ в нужную группу словаря, затем использовать его
   в компоненте. Не создавать константы с тем же текстом в каждом файле.
2. Не склеивать переводимые предложения из независимых фрагментов. Для имени
   компании или медиа использовать функцию сообщения с типизированным параметром.
3. Публичный текст, который должен менять менеджер, хранить в CMS. Словарь
   предназначен для интерфейса и безопасных запасных значений.
4. Не переводить slugs коллекций, имена полей и значения состояний.
5. Новые словари проверять через `satisfies Messages`; большие группы разбивать
   по смыслу, соблюдая лимит файлов проекта.

## Что потребуется для второго языка

Добавить полный словарь и язык в реестр; определить языковые URL и способ
выбора языка запроса. Передавать одну и ту же locale в серверные `getMessages`
и клиентский provider, включая preview. Сейчас серверный путь использует
единственный русский язык по умолчанию.

Отдельно включить локализацию необходимых полей Payload с миграцией контента;
согласовать fallback, SEO, hreflang, sitemap, slugs и правила публикации
переводов. Язык административного интерфейса и язык редактируемого материала
должны выбираться независимо. Подключить соответствующий пакет перевода
Payload и проверить длинные подписи, даты, числа и отсутствующий перевод.

Наличие словарей само по себе не делает содержимое сайта многоязычным.
