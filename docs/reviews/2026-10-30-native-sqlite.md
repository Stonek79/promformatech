# Переход на SQLite и выпуск без Docker

Дата: 30.10.2026. Изменения локальные, без commit/push и без подключения к домашнему или удалённому серверу.

## Сделано

- SQLite-адаптер той же версии Payload 3.91.0; WAL, ожидание блокировки 5 секунд, blocksAsJSON. Next/React не обновлялись.
- Новая исходная схема из текущих коллекций. Миграция повторяется безопасно, проверяет ledger, не запускает dev schema push в production. SQL разбит на модули до 300 строк.
- Worker использует файловую блокировку SQLite и восстанавливает прерванные медиа. На VPS один проход по timer освобождает память между задачами; CPU/память worker ограничены unit-файлом.
- Удалены PostgreSQL-зависимости, Compose, PG-specific проверки/импорт, архив заявок, rate-limit storage, почтовая очередь и старые поля формы. SMTP восстановления паролей сохранена. Типы CMS перегенерированы.
- Сборка standalone; отдельно упакованы CLI и все production-зависимости. Проверка запускает пакет вне дерева проекта, чтобы не использовать исходные node_modules. `.env` исключается даже если Next скопировал его в standalone.
- GitHub Actions для Ubuntu 24.04 x64, архив и checksum; на VPS не нужны сборщик и pnpm.
- Шаблоны Nginx, systemd web/worker/backup, скрипты обновления и согласованного snapshot. Предусмотрен внешний restic-репозиторий. Без него backup сообщает о неполной настройке, а не выдаёт локальную копию за внешнюю защиту.
- Обновлены инструкции VPS, домашнего стенда и справка менеджера.

## Проверки

- `pnpm check`: типы, Biome, CSS, ограничение размеров файлов, 118 существующих и адаптированных unit-проверок.
- `pnpm test:integration`: отдельная пустая SQLite; повторная миграция, вход владельца, черновик и опубликованная версия, история версий, настоящая обработка изображений, восстановление прерванной задачи. Временная среда удаляется.
- Выборочный Chromium: 6 сценариев из site, admin-settings, api-workflows — редактор, preview, публикация, настройки, приватность и медиа. Вся историческая визуальная матрица не прогонялась.
- Production build Next/Turbopack и проверка автономного пакета: мигратор, владелец, seed, worker, нативные SQLite/Sharp, сайт/CSS, вход, два runtime-домена без пересборки. Проверка выполняется вне исходников.
- Shell-скрипты проходят `bash -n`; systemd и Nginx на macOS не запускались.

Полный набор тестов не расширялся: удалены проверки вырезанной функциональности и PostgreSQL-переноса, четыре старых теста worker-lock заменены двумя проверками реальной файловой блокировки. Новые отдельные тестовые пакеты не устанавливались.

## Что ещё проверять на инфраструктуре

GitHub workflow подготовлен, но ещё не запускался в удалённом репозитории. Локальный артефакт macOS ARM не подходит для VPS; боевой пакет должен пройти тот же smoke на Linux runner. Память и скорость на VPS пока не измерены, гарантии минимального RAM нет.

На Ubuntu остаются практическая проверка unit-файлов, Nginx/TLS/продления, выключения и обновления, внешнего restic и восстановления. Сертификат и защита канала от объёмного DDoS зависят от домена/провайдера. Локальная полная копия медиакаталога может занимать много места и увеличивать простой, если файловая система не поддерживает reflink; после первой restore-проверки нужно назначить retention.

Старые локальные PostgreSQL-данные и медиа не удалялись. Для обновления существующего домашнего `.env` требуется новый DATABASE_URL и отдельный MEDIA_ROOT: `env:init` намеренно не перезаписывает пользовательский файл. Подробно: [домашний сервер](../deployment/home-server.md), [VPS](../deployment/native-vps.md).
