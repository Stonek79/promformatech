# Удаление формы и проверка готовности

Дата: 30.10.2026. Проверено локально на macOS arm64 с Node.js 22.22.0 и pnpm 10.12.4.

## Выполнено

- Удалены публичная форма, её CSS, клиентская валидация и обработчик `/api/inquiries`.
- Прямое создание обращений через `/api/leads` запрещено, в том числе для менеджера. Ранее полученные обращения остаются закрытым для посетителей архивом со статусами и комментариями.
- Блок формы нельзя выбрать в редакторе. Сохранённые блоки исключаются при чтении и сохранении; восстановление старой версии не возвращает форму на сайт.
- Убрана вкладка настройки формы. Справочник менеджера и актуальная памятка обновлены.
- Политика исключена из маршрутов, CMS-списков, публичного API страниц, поиска и sitemap. Ссылки на неё удаляются из настроек меню/подвала; публичный renderer дополнительно отфильтровывает их.
- Новое начальное наполнение не создаёт форму, её настройки и политику. Кнопка на первом экране ведёт на контакты; старый контактный якорь ведёт на контакты в подвале.
- Устранена обнаруженная невоспроизводимость генерации токенов: `tokens:build` теперь сам форматирует результат. До исправления `prepare:app` менял формат отслеживаемого CSS, хотя значения токенов оставались теми же.

Существующая схема хранения прежних блоков/настроек пока сохранена для тестовых баз и истории версий. Она скрыта и не используется публичным интерфейсом. Рабочие локальная и домашняя базы не очищались. Для предложенного чистого старта на SQLite перенос этой схемы и данных не требуется.

| --- | --- |
| `pnpm check` | PASS: Biome, предел 300 строк, TypeScript, CSS, токены, 122 unit-теста |
| `pnpm test:media` | PASS: 13 тестов, настоящие Sharp и FFmpeg/ffprobe |
| `pnpm test:e2e` | PASS: 66 сценариев Chromium; отдельные БД `promformatech_e2e`, медиа и Next output |
| Production build | PASS: `NEXT_OUTPUT_DIR=.next-verification pnpm build`, Turbopack; публичного обработчика `/api/inquiries` нет |
| Gitleaks | PASS: read-only скан `src`, `scripts`, `tests`, вывод с редактированием значений |
| Визуальная проверка | Снимки контактов desktop/light и mobile/dark с увеличенным текстом; форма и политика отсутствуют |

В E2E специально создана имитация ранее опубликованной политики: проверены not-found/noindex, отсутствие её в API, поиске и sitemap. Проверены запрет обоих путей приёма обращений, сохранность доступа менеджера к архиву, отсутствие вкладки формы в настройках и отсутствие формы в preview. Сохранены проверки черновиков, публикации, ролей, медиа, тем, размеров текста и адаптивности.

Первый typecheck обнаружил ссылки на удалённый route в старых автоматически созданных `validator.ts` в `.next*`. Очищены только соответствующие каталоги генерируемых типов, затем типы созданы заново. Исходные данные и медиа приложения не удалялись.

Локальные протоколы: `app/artifacts/feedback-removal/{check,e2e,build,secrets}.log`. Скриншоты и трассы — в `app/test-results/`; эти результаты не являются production-приёмкой и не хранятся в Git. Тестовый Next завершён, созданная для прогона БД удалена; рабочая база и её Docker-том сохранены.

## Что ещё требуется

1. **Архитектура ограниченного хоста.** Подготовить выбранный выпуск без Docker, оценить чистый SQLite-старт; текущий код по-прежнему использует PostgreSQL. [Предложение и порядок доработок](../architecture/native-sqlite-hosting.md).
2. **Поставка и обновления.** Linux-артефакты web/worker/служебных команд, CI, установка готового релиза и проверенный возврат к предыдущему совместимому релизу. Сейчас `.github` workflow и production-поставка отсутствуют.
3. **Постоянные процессы.** `systemd` для старта после перезагрузки, рестарта после сбоя и журналирования. `tmux` защищает только от закрытия SSH и не заменяет supervisor.
4. **Инфраструктура.** Nginx, домен, TLS и автопродление, ограничения запросов и загрузок, закрытые внутренние порты. Сетевую DDoS-защиту обеспечивает площадка/пограничный сервис; приложение не гарантирует защиту канала.
5. **Восстановление.** Внешние копии базы, медиа и секретов; проверка восстановления на чистой машине. Локальная копия на том же диске не закрывает потерю сервера.
6. **Ресурсная приёмка.** Замеры на Linux с целевыми CPU/RAM: обычные страницы, админка, загрузка, обработка длинного видео, обновление и восстановление. Локальные зелёные тесты не доказывают достаточность 1–2 ГБ RAM.
7. **Контент и менеджер.** Владелец подтверждает телефоны/адреса, менеджер проверяет своё обычное наполнение на реальных материалах. Safari/Firefox, физические iOS/Android и длительные видео требуют отдельной приёмки. SMTP для восстановления пароля и архивных уведомлений пока не настроен.

Итог: текущую версию можно проверять на домашнем стенде. Завершённость production-развёртывания не заявляется. Старый план U5–U9 с Docker требует замены части о поставке на native/systemd; он не исполняется автоматически этим изменением.
