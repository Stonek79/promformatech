# Дизайн-система и UI kit «ПромФормаТех»

Дата: 21.10.2026.
Спецификация реализации R19/KTD14/U8 основного [плана](../plans/2026-10-21-2144-feat-website-manager-mvp-plan.md).
Токены реализованы в `app/src/design-system/tokens/theme.mjs`, компоненты — в `app/src/components/ui`. Проверки и фактические ограничения фиксируются в отчёте реализации.

## Назначение

Сохранить оформление текущего сайта и управлять им из одного места.
Компоненты получают цвет, размер текста, отступы и оформление состояний из семантических токенов.
CSS Modules отвечают за локальную структуру и композицию, а не хранят независимые копии визуальных значений.

## Слои

| Слой | Содержание | Потребитель |
|---|---|---|
| Базовые токены | Палитра бренда, шкалы размера, интервалы, толщины линий | Семантические токены |
| Семантические токены | Основной текст, фон карточки, акцент, граница, ошибка, фокус, отступ раздела | UI kit и композиции |
| Компонентные токены | Размеры и варианты конкретного элемента, когда семантической шкалы недостаточно | Один компонент UI kit |
| Адаптивные правила | Плавные диапазоны и именованные условия изменения структуры | Генерируемые CSS-переменные и условия |
| UI kit | Небольшие компоненты, их состояния и варианты | Публичные страницы и собственные дополнения CMS |
| Композиции | Шапка, карточка продукции, страница проекта, форма заявки | Экраны сайта |

Названия переменных имеют префикс `--pf-`, например `--pf-color-text`, `--pf-font-size-heading`, `--pf-space-section`.
Повторно используемое значение получает смысловое имя, а не имя по конкретному экрану.
Палитра и шкалы извлекаются из исходного сайта; фактические значения утверждаются при сравнении с ним.
Менеджер не редактирует токены через CMS: он меняет содержимое готовых блоков.

## Единый источник и сборка

Источник токенов — машиночитаемое определение в `src/design-system/tokens/`.
Оно содержит значения, ссылки между токенами, границы плавного изменения и определения responsive-условий.
Небольшой build-скрипт генерирует CSS custom properties и общие именованные условия для CSS; генерируемые файлы не правятся вручную.
Не вводить Style Dictionary или отдельный пакет только ради небольшого набора токенов MVP.

CSS-переменные используются в значениях деклараций; runtime `var()` не подставляется в условия `@media`.
Именованные custom media раскрываются при сборке средствами PostCSS из того же источника breakpoint-значений.
Плагин `postcss-custom-media` и способ передачи общего набора определений проверяются вместе с конфигурацией Next в U8; не полагаться на нативную поддержку custom media целевыми браузерами.
Сборка приложения остаётся штатной Next.js; PostCSS обрабатывает CSS, а не заменяет сборщик приложения.

## Что токенизируем

| Группа | Параметры |
|---|---|
| Цвета | Бренд, поверхности, текст, ссылки, границы, состояния, фокус |
| Типографика | Семейства, веса, размеры, межстрочные и межбуквенные интервалы |
| Размеры и интервалы | Контейнер, поля страницы, секции, карточки, формы, промежутки сетки |
| Геометрия | Толщины рамок, скругления, размеры иконок и элементов управления |
| Эффекты | Тени, прозрачность декоративных слоёв, длительности и easing |
| Слои | Порядок шапки, меню, диалогов и уведомлений |
| Адаптивность | Пределы fluid-размеров и именованные media-условия |

Фотографии, подписи, текст и метаданные медиа остаются контентом, а не токенами.

## Адаптивные значения

Размеры текста, полей страницы, межсекционных отступов и промежутков сетки могут плавно меняться через `clamp()` с заданными минимумом и максимумом.
Для текста используются `rem` и ограниченная viewport-составляющая; чистое масштабирование всего интерфейса относительно `vw` не применяется.
Смена колонок, вида меню и размещения панелей происходит ступенчато по именованным условиям из общего источника.

Тонкая граница, контраст фокуса и минимальная область нажатия не обязаны уменьшаться вместе с экраном.
Их значения тоже принадлежат дизайн-системе; адаптивность не должна делать управление мелким или стирать рамки.
Акцентная рамка может иметь разные размеры в рамках заданной шкалы, если это нужно для сохранения оформления.

В режимах предпросмотра используется одна система токенов; отдельные копии переменных для трёх устройств не создаются.
Viewport-адаптация проверяется в отдельных viewport/iframe-контекстах: изменение одной ширины родительского блока само по себе не меняет viewport-единицы или media queries.
Сценарии zoom/увеличения текста, reduced motion и минимальной ширины берутся из Responsive UI основного плана.

## Правила CSS Modules

Цвет, шрифт, интервал, радиус, тень, толщина рамки, размер контролов и длительность анимации берутся из семантических/компонентных токенов.
Нельзя повторять их литералами в модуле или inline-стиле, переносить `clamp()` с новыми визуальными числами в каждый компонент или вручную переопределять базовую палитру.
Локальная переменная может ссылаться на общий токен, если это делает назначение понятнее.

Технические значения `0`, `auto`, `100%`, единицы сетки `fr`, отношения сторон и количества колонок не обязаны превращаться в бессмысленные токены.
Проценты прогресса загрузки, размеры исходного фото и координаты измеренного позиционирования являются данными выполнения, а не визуальной шкалой.
Такие исключения фиксируются в правилах проверки; визуальный размер вроде отступа не становится исключением из-за использования процента.

Stylelint проверяет собственные стили; узкая проверка токенов выявляет неразрешённые визуальные литералы и ссылки на отсутствующие переменные.
Проверки не применяются к внутреннему CSS зависимостей Payload/Base UI.
Исключения должны иметь конкретное назначение; массовое отключение правила не считается соблюдением R19.

## Состав UI kit для MVP

Сначала создаются только элементы, используемые текущими экранами:

- `Container`, `Section`, `Stack`, `Grid` — каркас и интервалы.
- `Text`, `Heading`, `Link` — типографика и ссылки.
- `Button`, `IconButton` — варианты действий, состояния загрузки и отключения.
- `Field`, `Input`, `Textarea`, `Checkbox` — публичная форма и её сообщения.
- `Dialog`, `NavigationMenu`, `Accordion` — необходимые сложные взаимодействия на headless-примитивах.
- `Surface`, `Badge`, `Alert` — повторяющиеся поверхности, состояния и сообщения.

Продуктовые карточки, этапы сотрудничества и редактор проекта — композиции поверх UI kit, а не универсальные примитивы.
Галерея использует общий Dialog и элементы управления; новая библиотека добавляется лишь при недостающем поведении.
Не строить заранее календарь, data grid, сложные combobox и прочие элементы без сценария в MVP.

Для применимых компонентов описать default, hover, focus-visible, active, disabled, loading, invalid и success.
Названия размеров и вариантов конечны и типизированы; произвольные CSS-параметры не заменяют понятный API компонента.
Headless-библиотека отвечает за механику взаимодействия; общий API и визуальные состояния принадлежат нашему UI kit.

## Интеграция с Payload

Публичные стили изолированы от стандартной админки.
Общие брендовые токены подключаются к поддерживаемым переменным темы выбранной версии Payload через отдельный bridge.
Не переопределять внутреннюю вёрстку админки широкими глобальными селекторами.
Собственные dashboard, статусы медиа и панели получают общие токены и согласуются со штатными элементами.

Границы тем учитывают portals: диалог или выпадающая панель должны получать тот же набор переменных, что и их trigger.
Это проверяется для публичного сайта, дополнений админки и iframe-предпросмотра.
Сохранение штатных полей Payload предотвращает необходимость поддерживать отдельную собственную CMS-оболочку.

## Каталог и проверка

Небольшая защищённая страница каталога внутри того же Next-приложения показывает токены, компоненты и применимые состояния.
Каталог доступен при разработке и на закрытом стенде; публичный production-маршрут отключён.
Storybook и отдельная инфраструктура публикации библиотеки в MVP не обязательны.

U8 проверяет изменение токенов сразу в нескольких компонентах, работу portal, доступность, границы fluid-размеров и отсутствие неизвестных переменных.
Публичные экраны затем проверяются на матрице Responsive UI основного плана.
Существующий дизайн остаётся визуальным ориентиром: выделение токенов не разрешает самостоятельный редизайн.

## Реализованные настройки отображения (22.10.2026)

`theme.mjs` содержит светлую/тёмную семантические палитры и `textSizes`.
Генератор создаёт CSS для `data-site-theme`, native Payload `data-theme` и
`data-text-size`. Системная тема сайта следует `prefers-color-scheme`, админки —
штатному provider Payload с обновлением при смене системной темы.

`AppearanceControls` содержит переключатель светлой/тёмной темы и кнопку T ↕,
которая циклически меняет размер текста через `NEXT_TEXT_SIZE`. `Switch` —
нативная кнопка с `role="switch"`, `aria-checked`, доступной подписью и фокусом;
Space/Enter работают без ручного перехвата клавиш. Анимация учитывает reduced motion.
Кнопка размера показывает ступень и сообщает текущий размер скринридеру.
Видимых надписей, меню и модальных окон у этих настроек нет.
`useDarkTheme` подписывается на системную тему через `useSyncExternalStore`;
после ручного переключения сохраняется явная тема. Сайт/админка сохраняют
независимые cookies; на сервере значения валидируются и применяются к HTML.
Цвет фона кнопки и её текста имеют отдельные контрастные семантические токены;
эта же пара используется для номеров этапов и заголовков услуг.
Hero повторяет композицию исходного сайта: фотография заполняет весь баннер,
текст и CTA находятся поверх неё на всех экранах. Белый текст имеет тень;
равномерный полупрозрачный слой меняется с темой (28% / 38%), без глухой заливки
половины фотографии. Высота может расти вместе с переносами крупного текста.

Переключение размера меняет только `text-scale` (1 / 1.125 / 1.25), который
входит в вычисления типографических токенов. Корневые размеры сайта и Payload
остаются постоянными: контейнеры, поля, иконки и сетка не масштабируются.
Общий контейнер заполняет экран до 120rem (1920 px при стандартном шрифте
браузера), затем центрируется. Шапка, основная область и подвал используют
одну ширину и одинаковые боковые поля; длина текстовых строк ограничена отдельно.
Это не отключает штатный zoom или пользовательские настройки шрифта браузера.

`Skeleton` — декоративный UI-примитив, `PageSkeleton` — композиция сайта с одним
доступным status. Размеры и анимация заданы токенами; reduced motion отключает
движение. Изображения используют `next/image` и готовые размеры media-worker,
а не отдельную систему обработки внутри UI kit.
