# Админка «ПромФормаТех»: минимальная версия

Дата: 21.10.2026.
Документ уточняет экраны и поля требований R4–R14 основного [плана](../plans/2026-10-21-2144-feat-website-manager-mvp-plan.md).
При расхождении поведения действует основной план; этот документ не добавляет отдельные технические механизмы.

## Основной принцип

Менеджер работает с содержимым сайта и видит результат перед публикацией.
Обычная операция не требует знания URL, HTML, SEO, размера картинки или кодека видео.
Внешний вид самой админки — аккуратно оформленный Payload с логотипом компании, русскими названиями и минимальным количеством полей.
Собственные элементы админки используют общую [дизайн-систему и UI kit](../design-system/design-system-and-ui-kit.md) по R19 плана.
Штатные элементы Payload согласуются с ней через поддерживаемые переменные темы, без переписывания всей админки.

## Обзор

На первом экране — кнопки «Добавить продукцию», «Добавить проект», «Изменить главную» и «Открыть сайт».
Ниже — новые заявки, последние изменённые материалы и состояние загруженных файлов.
Техническую очередь jobs не показывать менеджеру вместо состояния материала.
Если данных ещё нет, объяснить первое действие, а не оставлять пустую таблицу.

## Страницы

| Поле | Назначение | Поведение |
|---|---|---|
| Название | Заголовок материала в админке | Обязательно |
| Заголовок страницы | Что видит посетитель | По умолчанию равен названию |
| Содержимое | Готовые блоки | Добавление, порядок, скрытие |
| Статус | Черновик или опубликовано | Всегда виден рядом с действиями |
| Адрес страницы | URL | Создаётся автоматически; изменение — в дополнительных настройках |
| Поисковое описание | SEO title, description, изображение | Не мешает обычному сохранению |

Набор блоков MVP: текст; текст с фотографией; фотогалерея; видео; список характеристик/этапов; карточки выбранной продукции/услуг/проектов; призыв связаться.
Все блоки используют существующее оформление.
Набор не является свободным редактором CSS, колонок и произвольных скриптов.

Страница «Контакты» ссылается на общие контакты сайта, а не содержит их независимую копию.
Правовые страницы редактируются тем же механизмом; содержание подтверждает владелец.

## Главная страница

Редактор повторяет порядок существующей главной:

1. Первый экран: изображение, заголовок, подзаголовок, текст и цель кнопки.
2. О нас: заголовок, краткий текст, изображение, ссылка на страницу компании.
3. Услуги: заголовок и выбор карточек из раздела «Услуги».
4. Этапы сотрудничества: заголовок, упорядоченный список названий, описаний и сроков.
5. Форма связи: тексты из общих настроек формы; обработчик не редактируется менеджером.

Можно менять порядок и видимость блоков по R4/R5, сохраняя их визуальный стиль.
Шапка, меню, контакты и подвал изменяются в «Общих данных сайта».
Чтобы изменить один общий текст, менеджеру не нужно открывать каждую страницу.

## Карточка продукции

Вкладки: «Содержание», «Фото и видео», «Дополнительно».

| Поле | Обязательность | Пояснение менеджеру |
|---|---|---|
| Название | Да | Например: «Пресс-форма для корпуса прибора» |
| Краткое описание | Да | Что это и какую задачу решает |
| Подробное описание | Нет | Возможности, применение, особенности |
| Главное изображение | Да перед публикацией | Фото для списка карточек |
| Галерея | Нет | Можно менять порядок и подписывать фото |
| Видео | Нет | Загрузите файл; сайт подготовит его автоматически |
| Характеристики | Нет | Простые строки «Название — Значение», например материал |
| Группа | Нет | Для группировки выставочных материалов без сложной таксономии |
| Порядок | Нет | Положение на странице продукции |

Торговые поля исключены по R3.
Дополнительные SEO-поля и URL создаются автоматически, но доступны для осознанной правки.
Предпросмотр показывает карточку с текущим оформлением сайта.

## Карточка проекта и услуги

У проекта: название, краткое описание, задача клиента, выполненное решение, результат, главное изображение, галерея, видео и порядок.
Обязательны название и краткое описание; для публикации также главное изображение.
Поля задачи, решения и результата помогают писать понятный кейс, но не блокируют черновик, если материала ещё нет.
Название клиента и местоположение — необязательны и заполняются только для разрешённых к публикации данных.

У услуги: название, краткое описание, основное содержимое из блоков, изображение и порядок.
Карточки главной ссылаются на услуги; описание услуги не копируется вручную на главную.

## Фото и видео

Сетка миниатюр с названием, типом, размером и состоянием.
Фильтры: все, фотографии, видео, обрабатываются, с ошибками.
Материал можно выбрать повторно для другой карточки без повторной загрузки.

Состояния для менеджера:

| Состояние | Сообщение и действие |
|---|---|
| Загружается | Процент передачи файла; это не процент перекодирования |
| Ожидает обработки | «Файл загружен. Подготовим его для сайта» |
| Обрабатывается | «Готовим файл. Можно продолжить работу с текстом» |
| Готово | Миниатюра, просмотр и выбор для карточки |
| Ошибка | Понятная причина и доступный повтор |

Для фото — альтернативное описание, подпись, выбор главного изображения и области кадрирования.
Для видео — название, подпись, обложка и просмотр готового результата.
Настройки кодеков и качества скрыты от менеджера по Media Policy основного плана.
Лимиты загрузки показываются до выбора файла.
При обрыве MVP предложит загрузить незавершённый файл заново; повтор обработки сохранённого исходника его не перезагружает.

Медиа не удаляется физически, если используется опубликованной или сохранённой версией материала.
Первое действие — «Убрать из карточки» либо архивирование; освобождение диска выполняется служебной процедурой с учётом версий и backup.
Менеджеру перед действием показываются связанные материалы.

## Общие данные сайта

| Группа | Данные |
|---|---|
| Компания | Название, краткое описание, логотипы |
| Контакты | Телефон, email, адрес, время работы, ссылки на мессенджеры |
| Меню | Пункты, подписи, порядок, видимость, ссылки на страницы |
| Форма связи | Заголовок, пояснение, подписи полей, кнопка, сообщения успеха и ошибки |
| Подвал | Тексты, ссылки, подпись авторских прав |
| Правовые ссылки | Политика, согласие, cookies |
| Поисковые значения по умолчанию | Название сайта, описание, изображение для ссылок |

Телефон для отображения и звонка формируется из единого согласованного значения.
Публичный email и служебный получатель заявок — разные поля с разными правами.
Менеджер не вводит SMTP-пароль, ключ backup или параметры сервера.

## Заявки

В списке: дата, имя, контакт, источник и статус.
В карточке: сообщение посетителя, ссылка на исходную страницу, комментарий менеджера и состояние уведомления.
Статусы MVP: «Новая», «В работе», «Закрыта», «Спам».
Отправка письма не является доказательством наличия заявки — источником служит сохранённая карточка.
Права доступа и жизненный цикл персональных данных задаёт основной план R7/R14/R17.

## Публикация и ошибки

Действия: «Сохранить черновик», «Предпросмотр», «Опубликовать», «Снять с публикации» и «История изменений».
Обычный порядок: внести изменения → сохранить черновик → открыть предпросмотр → проверить → отдельно нажать «Опубликовать».
«Предпросмотр» открывает страницу с реальным оформлением сайта, сохранёнными изменениями и разрешёнными черновыми медиа.
Изменённые общие данные, например телефон или меню, тоже можно проверить до публикации.
В режиме предпросмотра видна плашка «Предпросмотр — изменения ещё не опубликованы» и действие «Вернуться к редактированию».
Предпросмотр предлагает три режима: «Десктоп», «Планшет», «Телефон»; для проверки на устройстве доступна обычная адаптивная страница.
Публичный сайт продолжает показывать последнюю опубликованную версию; открытие и закрытие предпросмотра ничего не публикуют.
Предпросмотр доступен только авторизованному сотруднику. Тестовая отправка формы из него отключена, чтобы не создавать реальные обращения.
Неполный материал можно сохранить, а перед публикацией менеджер видит конкретно недостающие поля.
Если новое обязательное медиа ещё обрабатывается, объяснить причину и оставить предыдущую публичную версию.
Не показывать «Опубликовано» после сетевой ошибки или неудачной записи.
При удалении материала сначала предлагать снятие с публикации/архивирование; необратимые действия — только владельцу по отдельной процедуре.

## Работа на разных устройствах

По R8 основного плана менеджер может выполнить основные действия с компьютера, планшета и телефона.
Для собственных компонентов админки используем визуальные и поведенческие соглашения Payload; публичная headless-библиотека не заменяет его формы целиком.
На небольшом экране навигация сворачивается, поля идут в удобном порядке, длинные списки сохраняют читаемость.
Кнопки сохранения, предпросмотра и публикации остаются доступными при открытой экранной клавиатуре.
Сенсорные операции не требуют hover, а подтверждение и ошибки показываются рядом с действием.
Критерии размеров, ориентации и доступности заданы в Responsive UI основного плана.

## Проверка с менеджером

Практическая сессия по Success Criteria основного плана:

1. Войти, найти продукцию и создать черновик.
2. Добавить описание, фото и видео; увидеть обработку и продолжить редактировать текст.
3. Предпросмотреть материал, изменить порядок фото и опубликовать.
4. У опубликованного проекта сохранить новую версию как черновик и проверить различие с публичной.
5. Изменить телефон, проверить шапку и подвал, восстановить прошлое значение.
6. Найти новое обращение и перевести его в работу.
7. Повторить основной сценарий на планшете и телефоне, проверить соответствующие режимы предпросмотра.

Разработчик наблюдает и записывает места, где потребовалась подсказка.
Техническая работоспособность формы не закрывает замечания к понятности.
