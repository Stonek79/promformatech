# Контракт runtime без Docker

Актуальная инструкция установки и обновлений — [VPS с SQLite](native-vps.md). Домашний dev-стенд — [отдельный документ](home-server.md).

- Сборка Next/Turbopack не подключается к рабочей базе и не получает её секреты. CLI для worker, миграций, seed и владельца упакован отдельно; production-зависимости устанавливаются только в CI.
- В production DATABASE_URL — абсолютный локальный `file:/.../site.sqlite`, SERVER_URL — HTTPS origin, PAYLOAD_SECRET — собственный стабильный секрет минимум 32 символа. MEDIA_ROOT лежит вне каталога релиза.
- В dev допускается относительный SQLite-файл и HTTP. Schema push работает только у web-процесса разработки. Миграции выполняются отдельной командой, не при старте production web.
- `/api/health/live` проверяет живой процесс; `/api/health/ready` — доступ к базе и соответствие migration ledger релизу. Worker не влияет на доступность чтения сайта.
- `APP_PROCESS_ROLE`: web, worker, migrator. Worker: последовательная очередь медиа и файловая блокировка базы с heartbeat. SQLite не размещается на NFS и не разделяется между несколькими VPS.
- SMTP необязателен, используется для восстановления паролей. Форма заявок, архив, уведомления и отдельный rate-limit storage удалены.

Обновление происходит с остановкой писателей и согласованной резервной копией. Предыдущие Docker/PostgreSQL-команды не применяются. Перенос пользовательского содержимого PostgreSQL не реализуется: исходная среда ещё не была production.
