# Удобство сайта и админки перед запуском

## Goal Capsule

Посетитель и менеджер могут читать интерфейс комфортным размером текста, выбирать тему и понимать, что происходит при загрузке и редактировании.
Средства: существующие Next.js, Payload, Base UI и дизайн-токены, без новых зависимостей и смены стека.
Основание — прямое поручение пользователя от 22.10.2026; правила `app/AGENTS.md` обязательны.
Работа локальная: реализация, проверка и отчёт. Реальная БД, аккаунты, медиа и публикации не меняются; commit/push/deploy не входят в поручение.

## Product Contract

### Summary

Добавить состояния загрузки, настройки отображения в обеих поверхностях и русские названия редакторских действий; сохранить фирменный фасад и функции черновиков/предпросмотра.

### Problem Frame

Во время загрузки футер появляется рядом с однострочным fallback; текст мелкий; пользователю недоступны очевидные настройки темы и масштаба; Payload выводит английские названия некоторых массивов.

### Requirements

| ID | Проверяемое поведение |
|---|---|
| R1 | До готовности страницы отображается узнаваемый скелетон; основная область резервирует высоту, футер не поднимается к шапке. Для готового контента искусственных задержек нет. |
| R2 | На сайте и в админке доступны светлая, тёмная и системная темы; системная реагирует на смену OS, явный выбор имеет приоритет. |
| R3 | В обеих поверхностях доступны обычный, увеличенный и крупный размеры текста. Выбор сохраняется после перезагрузки; начальное отображение учитывает сохранённое значение. |
| R4 | Настройки отображения личные для браузера и независимы для сайта и админки. Они не меняют CMS-контент и не требуют публикации. |
| R5 | Русские подписи добавления строк заданы для recipients, locations, people, navigation, footerLinks, specifications и обоих items массивов блоков. |

### Acceptance Examples

- AE1 (R1): при замедленном ответе виден status загрузки и скелетон; после завершения — содержание. Для короткой готовой страницы футер остаётся после основной области.
- AE2 (R2–R4): посетитель выбирает тёмную тему и крупный текст, обновляет страницу и видит тот же вид. Возврат к системной теме снова следует OS. Админская тема управляется штатным Payload provider.
- AE3 (R5): владелец открывает служебные настройки и видит «Добавить получателя»; менеджеру доступ к этой странице не добавляется.
- AE4 (R7): менеджер на планшете меняет тему/размер, открывает форму, сохраняет черновик и проверяет preview; посетитель продолжает видеть опубликованную версию.

## Planning Contract

- KTD1. **Сохранить стек и границы.** Server Components и чтение CMS остаются серверными; настройки вида — маленькие клиентские компоненты, общего state manager не требуется.
- KTD2. **Дизайн-токены являются источником визуальных значений.** Светлая/тёмная семантические палитры, шкала размеров, радиусы и скелетоны задаются в `app/src/design-system/tokens`; CSS генерируется штатной командой.
- KTD3. **Два владельца темы для двух корней.** На сайте — cookie, SSR-атрибут и CSS prefers-color-scheme. В админке — native Payload ThemeProvider; настройка system использует проверенный runtime contract, без `any` и патча зависимости. Для размера — собственные cookies и SSR htmlProps. Несохранённые CMS-поля не должны теряться при смене вида.
- KTD4. **Настоящая загрузка.** Использовать существующие Suspense/loading.tsx границы сайта, отдельный shell fallback и flex/min-height основной области. Не вмешиваться в внутреннюю маршрутизацию Payload ради skeleton.
- KTD5. **Локализация через схему.** `labels.singular/plural`, без переименования полей/миграций и подмены DOM-текста.

Исследование: `app/src/components/site/SiteShell.tsx`, `app/src/app/(site)/loading.tsx`, `app/src/design-system/tokens/theme.mjs`, `app/src/cms/admin-bridge.css`; установленная документация Next loading.js и исходники Payload ThemeProvider/RootLayout.
Ограничение совместимости: runtime Payload принимает auto, тип setTheme описывает только light/dark; адаптер должен быть локальным и проверяться браузерным сценарием. Native UI содержит px-размеры, поэтому масштабирование проверяется визуально, а не только через root font-size.

## Implementation Units

### U1. Loading

- **Requirements:** R1, R7.
- **Files:** `app/src/components/ui/Skeleton`, `app/src/components/site/PageSkeleton`, site loading/layout/globals.
- **Approach:** переиспользуемые декоративные блоки, один доступный status, reduced motion; резерв высоты main и shell.
- **Verification:** замедленный SSR/navigation, короткая страница, замена skeleton контентом; без задержек в продуктовом коде.

### U2. Appearance

- **Requirements:** R2–R4, R7.
- **Files:** `app/src/config/appearance.ts`, `app/src/features/appearance`, `app/src/cms/components`, token source/generator, оба layout, admin config/bridge.
- **Approach:** finite values и валидация cookie; переключатель темы вкл/выкл и кнопка с иконкой для циклической смены размера, без меню и модального окна; отдельные site/native-admin адаптеры. Основной текст сайта увеличить минимум до 1rem; базовый admin rem — постоянные 15px. Выбор размера меняет только типографические токены, без масштабирования контейнеров/полей/иконок. Проверять native формы и toolbar.
- **Verification:** theme/system/OS override/reload, размер/reload, клавиатурное переключение и цикл размеров, неизменность ширины контейнера/логотипа/иконок, большой текст и мобильный layout; некорректные cookies дают безопасный default.

### U3. Russian actions and search

- **Requirements:** R5–R7.
- **Files:** четыре schema-файла массивов, HeaderControls/Header styles и узкий вариант Button.
- **Approach:** добавить русские labels, округлую форму поиска и компактный доступный trigger настроек. Роли/данные/маршруты не меняются.
- **Verification:** owner/manager UI, восемь массивов, поиск/меню на узком экране и с клавиатуры.

### U4. Evidence and report

- **Requirements:** R7, R8.
- **Files:** `app/tests/e2e`, `app/artifacts`, `docs`.
- **Approach:** визуальный проход по фасаду/админке, проверка installed config; ограниченный статический security audit; план наполнения и production hardening по приоритетам. Оптимизации только с объяснимым эффектом, непроверенные гипотезы отдельно.
- **Verification:** повторить сценарии текущего полного прогона, где 23/25 успешны (navigation/pages требуют диагностики); не скрывать старые падения и не повышать timeout без причины.

## Verification Contract

Дополнение R9 по прямому поручению пользователя: `ResponsiveImage` с собственным
loader выбирает версии worker, poster использует `Image unoptimized`.
Проверки: реальные загрузки изображений, `srcset`, отсутствие повторного
публичного кеширования, существующие сценарии доступа к медиа и предпросмотра.

`pnpm check`: Biome, лимит 300 строк, TypeScript, Stylelint/токены, unit tests.
Браузерные тесты запускаются через `pnpm test:e2e` только на `promformatech_e2e`, отдельной media-директории и порту 3100, с отключённой SMTP.
После целевых проверок — полный suite и production build. Build не запускается одновременно с dev, использующим тот же output; при временной остановке dev восстановить.
Скриншоты: 390/820/1440, светлая/тёмная темы, крупный текст, формы и открытый portal. Проверить 320px и системное уменьшение движения.
Нет основания обещать конкретный LCP/TTFB выигрыш без измерения production-сборки; security source review не заменяет проверку инфраструктуры.

## Definition of Done

Уточнения пользователя: проверки медиа вынесены в именованные типизированные
предикаты; новые тексты переводятся через `src/i18n`; правила закреплены в
`app/AGENTS.md`. `publishedMediaIDs` отмечен в отчёте как следующий кандидат
на смысловую декомпозицию с сохранением кеширования и контроля доступа.

R1–R10 выполнены или имеют явно описанную проверочную/внешнюю зависимость. Фасад и админка доступны локально, сохранение/черновики/preview не регрессировали. Новые тесты проверяют поведение, а не копируют разметку.
Отчёт содержит результаты команд, ограничения, необходимые действия перед публикацией и порядок дальнейших улучшений.
Временные тестовые процессы остановлены; основная БД и медиа сохранены; экспериментальный/неиспользуемый код не оставлен.
