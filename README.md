# ПромФормаТех

Сайт-витрина на Next.js, Payload и SQLite. Менеджер редактирует материалы и медиатеку в админке, сохраняет черновики и проверяет изменения в предпросмотре.

## Локальная работа

Команды запускаются из корня репозитория.

```bash
pnpm --dir app install --frozen-lockfile
pnpm --dir app dev
```

Сайт открывается на `http://localhost:3000`, админка — на `/admin`. `pnpm dev` запускает сайт и обработчик медиа. Они останавливаются по `Ctrl+C`. [Настройка среды и команды приложения](app/README.md)

Перед пушем запустите `pnpm --dir app check`. Для изменений в редакторе, предпросмотре и локализации прогоните соответствующие сценарии `pnpm --dir app test:e2e`. Для изменений схемы SQLite используйте `pnpm --dir app test:integration` и проверьте миграции на копии существующей базы. [Локальные проверки](app/README.md#проверка-перед-коммитом)

## Что запускает релиз

PR в `main` запускает статические проверки. Пуш в `main` запускает **Native Linux release**, если изменился код сайта, миграции, ресурсы, зависимости, настройки сборки или серверные скрипты и службы. Правки только в README, `docs/`, `app/tests/`, `deploy/tests/` и настройках локальных тестов пропускаются. [CI](.github/workflows/ci.yml) · [Фильтр релиза](.github/workflows/release.yml)

Чтобы после пуша получить только артефакт, оставьте `VPS_AUTO_DEPLOY` выключенным. Для отдельной сборки откройте **Actions → Native Linux release → Run workflow**, выберите `main` и оставьте `deploy_to_vps` выключенным. Успешный запуск покажет `build: Success`, `deploy: Skipped` и артефакт `promformatech-<SHA>`.

## Деплой и обновления VPS

После локальных проверок отправьте нужный коммит в `main`. Для выкладки с Mac нужны pnpm, авторизованный GitHub CLI и [однократно настроенный SSH-доступ Actions](docs/deployment/automatic-deployment.md#доступ-github-actions-к-vps). Запускайте команду из корня репозитория.

```bash
pnpm --dir app deploy:vps
```

Команда запускает выкладку **текущего `main` на рабочий VPS**. GitHub Actions собирает и проверяет архив Linux x86_64, затем отправляет его на сервер. VPS проверяет архив, останавливает запись и создаёт свежий снимок SQLite и медиатеки в restic. После успешного резервирования сервер применяет миграции к рабочей базе и проверяет готовность нового релиза. База, медиа и настройки приложения хранятся отдельно от релиза в `/srv/promformatech/shared`.

Дождитесь `deploy: Success` в [GitHub Actions](https://github.com/Stonek79/promformatech/actions/workflows/release.yml). Затем проверьте главную, каталог, отображение медиа, вход менеджера и предпросмотр черновика. Если миграция завершилась ошибкой, проверьте журнал выкладки и снимок перед обновлением. [Резервное копирование и восстановление](docs/deployment/automatic-deployment.md#резервное-копирование) · [Ручное обслуживание VPS](docs/deployment/native-vps.md)

## Работа с контентом

Менеджер публикует правки через `/admin`. Для обновления текстов, фотографий и видео отдельная сборка сайта не требуется. [Справочник менеджера](docs/admin/manager-guide.md)
